# 3. Authentication

Authentication answers "who is calling". Decide it for people, for services and for agents separately.

## Checklist

- [ ] Every endpoint declares its authentication in the contract. Anything public is public on purpose.
- [ ] People authenticate through OAuth 2 with PKCE, following the security best current practice in RFC 9700. No implicit flow, no password grant.
- [ ] Services authenticate with client credentials, mutual TLS or signed assertions. Not with a shared static secret copied between teams.
- [ ] API keys, where used, are: generated by you, shown once, stored hashed, scoped to the least permission, tied to one environment, and easy to rotate with two keys valid during the changeover.
- [ ] Keys have a recognisable prefix and a checksum so that secret scanners can find leaked ones with few false alarms. GitHub's token format is the model.
- [ ] Restricted keys exist, so a consumer can hold a key that only reads one resource type.
- [ ] Access tokens are short-lived. Refresh tokens rotate.
- [ ] High-value tokens are bound to the sender, with DPoP (RFC 9449) or mutual TLS, so a stolen token cannot be replayed from another machine.
- [ ] The API publishes OAuth protected-resource metadata (RFC 9728) so that a client can discover which authorisation server protects it.
- [ ] Credentials never appear in URLs. Query strings are logged by every proxy on the path.
- [ ] Failed authentication returns 401 with a `WWW-Authenticate` header. Insufficient permission returns 403. For a missing OAuth scope, say which one: `WWW-Authenticate: Bearer error="insufficient_scope", scope="..."` (RFC 6750).

## Agents and delegation

- An agent acting for a person should carry a token that names both the person and the agent, with a narrow scope and a short life. Do not hand an agent the person's long-lived key.
- Prefer per-task credentials. If an agent needs to act for ten minutes, the credential should last about ten minutes.
- Record which agent made each call. One shared key across a human and an agent makes revocation impossible without an outage.
- OAuth 2.1 is still an Internet-Draft as of October 2026. Follow RFC 9700 today. It contains the same security requirements.
